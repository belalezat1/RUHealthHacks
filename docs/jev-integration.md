# Jev advisory integration

The backend uses one lifespan-owned HTTPX AsyncClient. `JEV_MODE=mock` is the local default; mock responses are deterministic, labeled, and report uncertainty. `off` returns a disabled result. `live` requires a confirmed TypeSafe sponsor/project API key on the backend. No key is placed in a Vite setting, response, or log.

The adapter uses the [official TypeSafe OpenAPI contract](https://api.typesafe.ai/openapi.json) and [quickstart](https://docs.typesafe.ai/introduction/quickstart): Bearer authentication, a single `POST /v1/systemone` containing state/model/questions, and authenticated `GET /v1/models` for the opt-in smoke test. The actual response model is recorded separately from the configured `jev-latest` alias. The application uses HTTPX only, not a second vendor SDK.

Three independent questions evaluate note ambiguity (Noul), handoff coordination difficulty (Score), and secondary preference among at most four already feasible physician plans (Choice, with `no_preference`). The instructions reference the exact input fields and treat operations notes as untrusted data. No feasible plan means no evaluation. The deterministic optimizer remains authoritative; none of these answers changes eligibility, clinical priority, consent, or assignments.

Response validation requires exact answer names and matching types. Noul has one finite 0–1 probability and no confidence field. Choice requires exactly the requested options and a selected highest-probability option. Score accepts fractional probability-weighted indices with an exact zero-based legend and range. Distributions must sum within 0.01 of one; confidence and probabilities must be finite 0–1 values. Missing answers, extra answers, invented candidate IDs, and changed legends are invalid.

The [provider's confidence documentation](https://docs.typesafe.ai/confidence) defines confidence as a summary of the answer distribution. It is not a measured chance of safe staffing, a hospital risk percentage, or clinical evidence. Local display thresholds flag Noul 0.25–0.75, Choice/Score confidence below 0.5, and deferred choices as uncertain. These thresholds are demo presentation policy, not calibrated safety claims.

The total application deadline is at most five seconds, including one possible transient retry and backoff. Auth and validation failures are never retried unchanged. Failed live calls remain unavailable/invalid and never become mock successes. Version/expiry changes discard the advisory. The ordinary 128-entry cache keys dataset, source version, proposal, input hash, rubric version, model, and mode; entries expire after at most 30 seconds. Dashboard polling does not invoke Jev.

Run contract/resilience tests with `cd backend && uv run pytest tests/test_jev.py -q`. After the organizer confirms credentials, run `JEV_MODE=live uv run python scripts/jev_smoke.py` from `backend` with `TYPESAFE_API_KEY` already supplied through the environment or an untracked environment file. The smoke test first confirms model availability, then validates a synthetic batch. It prints normalized status/model/usage only, never the key. No live smoke test has been claimed without a successful provider response.
